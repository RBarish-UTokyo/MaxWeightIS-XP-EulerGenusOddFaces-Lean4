# An XP algorithm for maximum-weight independent set in embedded graphs, in Lean 4

A Lean 4 and Mathlib formalization of Theorem 1 of *Maximum-weight independent
set in embedded graphs parameterized by Euler genus and number of odd faces*
(forthcoming), together with a provably correct implementation of the
algorithm as one fixed program for an explicit pointer machine.

* **What Lean proves.** There is one fixed finite program, a computable
  function `f` and absolute constants `C`, `b` such that, for every graph drawn
  in a closed surface of Euler genus `γ` whose complement has `k` regions of odd
  total boundary length, and for all rational vertex weights, the program
  outputs a maximum-weight independent set using at most
  `f(γ + k) · N ^ (D(γ, k) + C) · (L + 1) ^ b` bit operations, where
  `D(γ, k) = max {0, γ + k − 2, γ − 1}`, `N = |V| + |E| + 1` and `L` is the
  weight encoding length. On an orientable surface the exponent improves to
  `max {0, γ + k − 2}`.
* **Axioms.** The proof uses exactly Lean's three standard axioms
  (`propext`, `Classical.choice`, `Quot.sound`). There is no `sorry`, no other
  axiom and no `native_decide`.
* **Checking.** The Lean kernel checks the proof; Comparator checks that the
  solution proves the challenge statement and replays it with the toolchain's
  independent kernels (see [Checking](#checking)).

Author and maintainer: Robert D. Barish (rbarish@ims.u-tokyo.ac.jp).

## The statement

The statement is [`Challenge.lean`](Challenge.lean), generated by
[`scripts/gen_challenge.py`](scripts/gen_challenge.py) as a verbatim copy of
the single project module [`WeightedMIS/Statement.lean`](WeightedMIS/Statement.lean)
(Mathlib imports only), followed by the target

```lean
theorem WeightedMIS.Spec.main_claim : WeightedMIS.Spec.MainClaim
```

The proof is [`Solution.lean`](Solution.lean). The statement has four parts.

1. **The machine.** A sixteen-register pointer machine
   (`WeightedMIS.RegisterMachine`): a program is a finite table of closed
   procedure bodies built from loads, bounded cell allocations, register
   copies, Boolean branches, procedure calls and returns. There is no
   arithmetic instruction on unbounded numbers and no host-function
   instruction. The interpreter `FramedExec` records every heap event and the
   caller frame saved at every call.
2. **The cost.** `stackBitCost` of the run's call tree: every heap event costs
   `4` plus the binary lengths of the addresses it reads or writes, and every
   call additionally pushes and later pops the caller's sixteen register words
   bit by bit on an explicit symbol stack. This is a logarithmic-cost measure
   of bit operations.
3. **Surfaces and drawings** (`WeightedMIS.Spec`). A closed surface is given
   by a finite combinatorial *map*: a connected graph cellularly embedded in
   the surface, recorded by its flags (edge, side, endpoint) and the corner
   pairing of flags, the standard flag description of an embedded graph that
   covers orientable and nonorientable surfaces. Faces are the orbits of flags
   under `along` and `corner`, and the Euler genus is `E + 2 − V − F`. The
   input graph is a `Drawing` (a graph with its own corner pairing, possibly
   disconnected, noncellular, with loops, multiple edges and isolated
   vertices) together with a witness `D.In A` that it is a subdrawing of a
   closed-surface map `A`. Complementary regions are the faces of `A` glued
   across the deleted edges. The parameter `k` counts the regions whose
   *total* boundary-walk length, with multiplicity, is odd. For a cellular
   drawing these are the odd faces.
4. **Input and output.** The input heap is produced by a fixed encoding
   (`Spec.encode`). It holds the vertex words, one record per edge (its
   endpoint words and the keys of the corner partners of its four flags), and
   the weights in lowest terms (sign, absolute numerator, denominator), all
   written in binary in common widths. The run must return a pointer to a
   list of vertex words denoting a maximum-weight independent set.

`MainClaim` asserts that the run exists, that every run returns a
maximum-weight independent set, and that every run satisfies both cost bounds.
Runs are deterministic. The ambient map is a proof witness only: it is never
part of the input, and its size does not enter `N`.

### Modelling choices

* Combinatorial maps represent closed surfaces. Every graph drawn in a closed
  surface is a subdrawing of a cellular map of that surface, so quantifying
  over all ambient maps loses no generality. The theorem is stated for this
  finite representation; no topological realization theorem is formalized.
* `N = |V| + |E| + 1` counts the drawing only. The manuscript's
  `|V| + |E| + |F| + 1` differs by a constant factor, since the drawing has at
  most `4|E|` faces.
* All numbers in the input are written in fixed common widths
  (`indexWidth`, `weightWidth`). This padding changes the input length by at
  most a polynomial factor, which is absorbed into `N ^ C`.

### Constants

The witnesses are explicit (`WeightedMIS.MainTheorem`):

* the program is `WeightedMIS.FinalProgram.program`, a table of 634 procedure
  bodies, started at its top-level entry;
* `C = 44` and `b = 43`;
* `f(p) = (F + 100) · (102 + 35 · (F + 100 + p + 91))` with
  `F = 2 ^ 36 + 2 ^ 230 · 5 ^ p · (p + 6) ^ 42`, a computable function,
  single exponential in `p = γ + k`.

The constants bound the proof and say nothing about the program's practical
running time. The manuscript asserts only absolute constants, which these are.

## Relation to the manuscript

The program implements the manuscript's algorithm.

1. Truncate negative weights.
2. Compute an optimal half-integral point of the fractional independent-set
   polytope by an integral maximum flow on the double cover, using a
   capacity-scaling Edmonds–Karp solver.
3. Keep the half-valued vertices (weighted persistence) and split the
   residual graph into connected components.
4. On a bipartite component, take a colour class. The all-half point is
   optimal there, so a colour class is a maximum.
5. On a nonbipartite component:
   1. obtain nonnegative edge costs from a second maximum flow;
   2. build the alternating even-face rows `B`;
   3. compute a bounded integral complement `W` of their span in the
      incidence kernel by exact rational elimination;
   4. build the parity row `π` from an odd closed walk;
   5. run one shortest-path search in the sparse expanded state graph;
   6. read off the slack counts, propagate the integer potential, and
      threshold.
6. Assemble the components, restore the fixed vertices, and remove the
   originally negative vertices.

Points where the implementation differs from the manuscript's exposition:

* **The complement `W`** is computed from incidence-kernel generators by
  deterministic cycle decomposition and a greedy rank-increasing selection,
  not from an explicitly chosen odd unicycle. Every row still has entries of
  absolute value at most two. The number of rows is the dimension `d` of
  Lemma 6, so the exponent is the manuscript's.
* **Half-integrality and persistence** (Lemmas 3 and 4) are proved through the
  max-flow construction rather than the extreme-point argument.
* **Ribbons built during the run** are stored as key-indexed tables, and facial
  walks are traced by first return.

The parameter bound of Lemma 2, including the noncellular and disconnected
case and the orientable sharpening of Lemma 11, is proved for the components
the program actually computes. It is applied with the actual dimension of the
complement the program computes.

The manuscript is forthcoming and is not included in this repository. It
cites G. L. Nemhauser and L. E. Trotter, Jr., "Vertex packings: Structural
properties and algorithms", *Mathematical Programming* 8 (1975), 232–248,
doi:10.1007/BF01580444.

## Checking

The project pins Lean `leanprover/lean4:v4.35.0-rc2` and Mathlib commit
`065356127b1dc0016f66b7283ce0ce2c4055aa55`.

```sh
lake exe cache get
lake build                          # WeightedMIS, Challenge, Solution
./scripts/verify-comparator.sh      # Comparator, as Palomar runs it (needs bwrap)
python3 scripts/check-lean-sources.py
python3 scripts/refresh_audit.py && lake env lean Audit.lean
```

`Audit.lean` prints the transitive axioms of every public declaration of the
development; the generated records are in [`verification/`](verification/).

## Layout

* `Challenge.lean`, `Solution.lean`, `comparator.json`: the Palomar statement,
  proof and Comparator configuration.
* `WeightedMIS/Statement.lean`: every definition the statement uses.
* `WeightedMIS/`: the development. Its main parts are:
  * the mathematics: persistence, max-flow preprocessing, surface topology and
    parameter bounds, face matrices, kernel complements, the expanded search
    graph and recovery;
  * the executable solver `ExecutableMIS.solve`;
  * the machine programs with their `Within` event bounds;
  * the cost composition (`FinalBudget`, `FinalCost`, `FinalAccounting`);
  * the concrete program table (`FinalProgram*`, generated by
    `scripts/gen_program_table.py`);
  * the main theorem (`MainTheorem`).
